# ADR 0001 — Verify DB schema/RLS/RPCs with PGlite (no Docker)

**Status:** Accepted

**Context.** The build environment has no Docker and no local Supabase CLI stack,
so `supabase start` / `gen types --local` and live RLS tests aren't available.

**Decision.** Verify all SQL (schema, RLS policies, RPCs, seeds) by applying the
real migrations in **PGlite** (in-process WASM Postgres) with a small
Supabase-compatible shim (`auth` schema, `auth.uid()`, `anon`/`authenticated`/
`service_role` roles). Harness scripts live in the scratchpad `dbtest/` and
assert schema validity, RLS isolation, RPC idempotency/ownership, and seed
integrity. TypeScript DB types are generated by introspecting the applied PGlite
schema, matching the CLI's output shape.

**Consequences.** Fast, deterministic verification without Docker. The final
canonical types should still be regenerated with the Supabase CLI against the
real project (`docs/DATABASE.md`); storage policies can't be exercised in PGlite
(no `storage` schema) and are validated on `db push`.
